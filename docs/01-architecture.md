# Architecture and Core Contracts

> This is the **only design reference** when changing code. It records the invariants and design
> decisions you must not violate — it does not restate the implementation, which is the source of truth.
> Feature IDs (`TAG-01`, `NET-06`, `T1`–`T10`, ...) are defined in [02-development-guide.md](02-development-guide.md) §2.

## 0. Workspace and Dependency Direction

| Crate | Responsibility |
|---|---|
| `radicom` | Core library: data model, file IO, pixel, render, print, media, SR, anonymization, codec **interfaces** |
| `radicom-network` | tokio-based network layer: PDU, association, DIMSE C-/N-services, SCU/SCP, TLS |
| `radicom-json` | DICOM JSON (PS3.18) and Native XML |
| `radicom-dict` | Generated tag/UID/private dictionary tables from the pinned fo-dicom dictionary XML |

Dependencies flow one way: `radicom` depends on none of the other three; `radicom-network` and
`radicom-json` depend on `radicom`; `radicom-dict` is used only by `radicom`. Lower layers must never
depend on higher ones.

Design principles:

1. **fo-dicom semantics, Rust-idiomatic API** — do not copy the C# shape (no DI container, no inheritance
   hierarchies). Express the same capabilities with traits, generics and ownership.
2. **Zero-copy first** — large values (pixel data, big OW/OB) are always buffer references; uncompressed
   frames are slice views; strings and numbers evaluate lazily.
3. **Parsing decoupled from building** — the reader emits observer events only; dataset building,
   DICOMDIR stitching, SR, dump and JSON all reuse the same parser.
4. **Codecs fully decoupled from the core** — the core has zero compression-library dependencies; codecs
   are injected through a trait plus registry.
5. **Synchronous core, async network** — the data model and IO are synchronous (FFI-friendly, easy to
   test); the network layer is fully async.
6. **Lenient reading, strict writing** — the read path tolerates malformed data (T1–T10); the write path
   guarantees standard compliance.

## 1. Tag

### 1.1 Representation

```rust
pub struct Tag { group: u16, element: u16, private_creator: Option<Arc<PrivateCreator>> }
```

- `is_private()` is true for odd groups.
- Conversions to/from `u32` pack as `(group << 16) | element`.
- Constant `Tag::UNKNOWN` is `(FFFF,FFFF)`.

### 1.2 Equality and ordering (critical — dataset storage order depends on it)

| Comparison | Rule |
|---|---|
| Both public | compare `group`, then `element` |
| Both private, same group, same creator | compare **low 8 bits of `element` only** (block-relative order) |
| Anything else | compare `group`, then `element`, then the creator string |

`Hash` follows the same normalisation (private tags hash by group + low byte + creator).

**Do not "clean this up".** It keeps the sorted container stable across private blocks regardless of
which block a tag resolved to, and it matches fo-dicom. Changing it changes serialized byte order.

### 1.3 String formats

| Format | Example | Used by |
|---|---|---|
| General `(GGGG,EEEE)` / `(GGGG,EEEE:CREATOR)` | `(0028,0010)` | Display / parse default |
| No parentheses | `0028,0010` | Parse accepts |
| JSON `GGGGEEEE` (8 hex digits) | `00280010` | DICOM JSON |
| Masked | `(60xx,4000)` | `MaskedTag` only |

Parse failures return `Error::Data` carrying the offending input. Creator strings are interned through
the dictionary's creator cache.

### 1.4 Masked tags (TAG-05)

`MaskedTag { card: u32, mask: u32 }`. `parse("(60xx,4000)")` maps each hex nibble to `0xF` in the mask
and each `x` to `0x0`; `is_match(tag)` is `(tag.to_u32() & mask) == card`; display re-derives the `x`
positions from the mask. Consumers: repeating overlay groups, anonymizer wildcard rules, masked
dictionary entries.

## 2. VR, UID, Transfer Syntax, Dictionary

- **VR** — the 34 standard value representations. Metadata drives encoding: `is_16bit_length()` decides the
  explicit-VR length field width, `unit_size()` drives byte swapping and scalar reads, plus string /
  charset-sensitivity / multi-value predicates. Validation rules are in §5.
- **UID** — `Uid` holds an `Arc<str>` interned through a global registry. `Uid::parse` never fails (an
  unknown UID keeps its literal value); `query` returns `Option`. Private UIDs can be registered.
  `UidGenerator` produces `2.25.<decimal uuid>` UIDs and supports consistent remapping (the same source
  UID always maps to the same replacement).
- **Transfer syntax** — `TransferSyntax` records the UID, endianness, VR explicitness, and whether the
  pixel data is encapsulated/compressed. `syntaxes::*` holds the built-ins; `TransferSyntax::register` is
  the extension point used by application-defined syntaxes and by `radicom-codecs`.
- **Dictionary** — the public and private dictionaries are generated by `radicom-dict` and **must never be
  hand-maintained**. Private-tag VRs must be looked up in the private dictionary (located by creator
  block); returning `UN` for every private tag is a defect, not a design choice.

### 2.1 Naming

Constants are named after the **PS3.6 keyword** in SCREAMING_SNAKE_CASE, matching fo-dicom one-to-one
(`DicomTag.PatientName` ↔ `Tag::PATIENT_NAME`, `DicomUID.CTImageStorage` ↔
`uids::CT_IMAGE_STORAGE`). Do not add short aliases — a second name for the same value is a second thing
to keep in sync.

Use the constants at every call site:

```rust
use radicom::{syntaxes, uids, Tag};

ds.insert_value(Tag::PATIENT_NAME, "Doe^John");
ds.insert_value(Tag::SOP_CLASS_UID, uids::CT_IMAGE_STORAGE);
ds.set_transfer_syntax(syntaxes::EXPLICIT_VR_LITTLE_ENDIAN.clone());
```

Never write `Tag::new(0x0010, 0x0010)` or a UID literal. The constants are generated from the dictionary,
so they cannot drift from it.

## 3. Dataset and Elements

- **Storage** — `BTreeMap<Tag, DicomItem>`. Iteration order *is* tag-ascending order and the writer
  depends on it. Switching to `HashMap` would break byte-level round-trips.
- **`normalize_read`** — reading a private tag resolves it to its real address inside the creator block.
  **Every read path must go through it**; querying the underlying map directly misses private elements.
- **Zero-copy large values** — `ElementValue::as_buffer()` returns `Arc<dyn ByteBuffer>` which may be a
  `MemoryBuffer`, a `FileWindow` (a region on disk) or a `BulkDataUri`. **Never assume it is in memory**;
  call `data()` only when you actually need the bytes, because that materialises them.
- **Numeric reads** — the integer and float `FromElement` impls accept both string VRs (IS/DS parsing) and
  binary VRs. A binary read advances at the **VR's own `unit_size()`** and widens/sign-extends to the
  requested type, so `u32` from `US` and `f64` from `US` both work, at any index.
  **Do not reintroduce `unit_size().max(T::SIZE)`.** That strides by the destination width, reads past the
  element and silently yields 0 — the exact root cause of Rows/Columns reading as 0 on real files (and
  therefore of `get_frame` returning empty frames).
- **`insert_value` VR resolution** — the **dictionary VR is authoritative**. A numeric value's own
  preference (`IS` for integers, `DS` for floats) is only a hint and is replaced by the dictionary VR
  whenever both are numeric: `Tag::ROWS` → `US`, `Tag::NUMBER_OF_FRAMES` → `IS`,
  `Tag::RESCALE_INTERCEPT` → `DS`. A non-numeric hint (a string written to a binary tag) keeps the
  caller's choice, because that value cannot be silently re-encoded. Without this rule
  `insert_value(Tag::ROWS, 512u16)` wrote an `IS` string — non-conformant bytes that round-tripped only
  because the reader made the same mistake.

## 4. Character Sets (ENC-01..04)

- Driven by `(0008,0005) Specific Character Set`, including ISO 2022 escape-sequence switching and
  multi-byte encodings.
- Decoded values are always UTF-8.
- A `SpecificCharacterSet` list with an empty leading term resolves to its first non-empty term
  (`\ISO 2022 IR 58` → GBK, `\ISO 2022 IR 87` → ISO-2022-JP).
- **Single-byte `ISO_IR nnn` terms must map to the corresponding ISO-8859-x**, never to a Windows code
  page. Mapping them to Windows-125x is a known defect (§15).

---

## 5. Validation (VAL-01..03)

- Validation can be disabled globally, per scope (`ValidationScopeGuard`) or per dataset.
- A failure returns `ValidationFailure`, strictly distinct from a parse error: **validation may be
  skipped, parsing may not**.
- `Dataset::validate()` is on demand, like fo-dicom's `Validate()`. The writer and parser deliberately do
  **not** call it, so tolerant real-world round-trips keep working.

---

## 6. Buffers and IO (BUF / IO)

- The `ByteBuffer` trait separates `size()` from `data()`: `size()` must be cheap and must not
  materialise, `data()` may.
- **`FileWindow` is a region on disk, not loaded content.** Any path that promises not to read large
  values must not call `data()`.
- Byte sources and targets are generic over `Read + Seek` / `Write`, so memory and files share one
  parser implementation.
- Async code must not perform blocking file IO on a runtime worker thread; use `spawn_blocking`.

## 7. Reader (RD-01..05) and Tolerance Rules T1–T10

The reader emits observer events and does not build datasets directly. The recursion depth cap defaults
to 256.

Lenient reading is a core acceptance criterion, not a nicety:

| Rule | Situation | Handling |
|---|---|---|
| T1 | Explicit VR bytes are two spaces | use the dictionary VR, stay explicit |
| T2 | Explicit VR is garbage | rewind, parse that element as implicit |
| T3 | UN with undefined length that is really SQ | parse as SQ (inner LE when outer is BE, CP-246) |
| T4 | Private SQ encoded explicitly inside an implicit dataset (and the inverse) | probe, then switch mode for the subtree |
| T5 | Orphan item tag | implicit undefined-length SQ |
| T6 | Fragment sequence missing its final delimiter at EOF | accept (fo-dicom #1339) |
| T7 | SQ ends directly with a sequence delimiter where an item was expected (k-pacs style) | accept |
| T8 | Trailing garbage after the dataset | ignore |
| T9 | Group length element with VR UN | treat as UL |
| T10 | Deflated syntax | transparently decompress |

**CP-246 condition**: a `UN` with *defined* length that is **not private** is read as a sequence whose
inner content is little endian even when the outer syntax is big endian. Inverting this condition makes
big-endian UN sequences read the wrong length.

A fragment sequence's `FFFE,E0DD` item delimiter **must consume its 4-byte length field**, exactly like
the `FFFE,E000` item branch does. Breaking out without consuming it desynchronises the stream for every
remaining element.

## 8. Writer (WR-01..03)

- Strict output: group lengths, padding and length rules must be compliant.
- Sequences and items may be defined or undefined length, chosen by `WriteOptions`.
- Numeric values are byte-swapped to the target syntax; chunk boundaries must respect unit alignment.
- The file meta group always recalculates `(0002,0000) FileMetaInformationGroupLength` (Type 1),
  regardless of the dataset-level group-length option.
- ACR-NEMA format is rejected on save.

## 9. Pixel Data and the Codec Boundary (PIX / CODEC / TR)

### 9.1 This is the normative interface contract for the outside world

Changing it breaks `radicom-codecs`.

- `PixelData` is the **single** read/write gate for pixel data. Codecs, the transcoder and the renderer
  must all go through it; nothing may touch `(7FE0,0010)` directly.
- A `Codec` implementation must:
  - touch the dataset only through `PixelData` property setters, never other elements;
  - map every failure to `Error::Codec` and **never panic**;
  - not consume the input buffer when it does not decode (the buffer may be reused);
  - tolerate upper/lower case bit differences in the DICOM tag name when the underlying file is
    noncompliant (DICOM tag names are case-sensitive).
- This repository ships **zero built-in codecs** (divergence D10). The `pixel::codec` traits and registry
  are the frozen boundary that `radicom-codecs` implements.
- `Transcoder` selects a codec from the registry by transfer syntax. When none is registered it returns
  `Error::Codec`; it must **never fall back to pretending success**.
- Frame-size math must handle 1-bit packing (`rows * ceil(columns / 8)`), YBR 4:2:2 and 4:2:0 chroma
  subsampling, and multi-frame slicing. A zero-sized frame is an error, not an empty success.

### 9.2 Photometric interpretation and LUTs

- Photometric Interpretation dispatches to the correct conversion path; dispatch on the interpretation,
  **not** on samples-per-pixel (palette is single-sample but must use the palette path).
- Fixed stage order: Modality LUT → VOI LUT (window or LUT sequence) → Presentation LUT → color
  conversion.
- A 16-bit VOI LUT output range is `0..2^n-1` and must be rescaled to that range — **not** shifted right
  by 8.
- LUT descriptors (entry count, first mapped value, VR, signedness) must be validated. Entry count `0`
  means 65536. Values outside the table clamp to the nearest endpoint.
- XA/XRF display skips the modality LUT (Clunie guidance).

## 10. Rendering (REND-01..11)

- Entry points are `render_frame(&Dataset, frame)` and `DicomImage`, both producing `RawImage`.
- `GrayscaleRenderOptions` decides where the window comes from, in priority order: explicit values →
  dataset window tags → per-frame functional group `(0028,9132)` → VOI LUT sequence → smallest/largest
  pixel value → histogram → min/max.
- Stored values must be normalised to the low `bits_stored` bits (drop high-bit padding) **before**
  windowing. Every raw-pixel reader — grayscale, RGB, YBR, palette, MPR, icon — must do this; skipping it
  is how 12-bit-in-16 data renders wrong.
- Window values may live in `DS` (text) or `US`/`SS` (binary) attributes, so read a numeric attribute
  numerically first and fall back to text — never text-only.
- Output scaling, spatial transforms (scale/rotate/flip/pan) and MPR reconstruction are separate
  operators applied in that order.
- Export is `RawImage` plus hand-written PNG/BMP encoders; there is no external image dependency.
- Rendering failures must return an error, never silently produce a blank image.

## 11. Networking (NET / SRV / CLI / DIMSE)

### 11.1 Layering and task model

Transport (TCP/TLS) → PDU framing → association negotiation → protocol engine → DIMSE services →
client/server. One tokio task per association. Locks must not be held across `.await`.

### 11.2 PDU and association

- A PDU header is fixed 6 bytes: type (1) + reserved (1) + length (u32, big endian).
- Sub-item headers are `type (1) + reserved (1) + length (u16)` — 4 bytes, big endian. Only the P-DATA
  PDV length is 32-bit.
- Item values must have even length; pad odd values with a single `0x00` and strip trailing NUL/space on
  decode.
- An A-ASSOCIATE-RJ body is `reserved (1) + result (1) + source (1) + reason (1)`.
- Presentation context layout is uniform: `id (1) + reserved (1) + result (1) + reserved (1)`. The RQ
  writes result = 0; only the AC carries a real result. **Writing the result at offset 1 instead of 2
  turns every rejection into an acceptance in both directions.**
- An A-ASSOCIATE-AC echoes only `result` plus **one** accepted transfer syntax per context — no abstract
  syntax; the client refills the abstract syntax from its RQ by context id.
- User-information sub-items:
  - Role selection (`0x54`): `uid_len (u16) + uid + scu (1) + scp (1)`.
  - Extended negotiation (`0x56`): the application information is a **flat byte array** where the index is
    the field number — not `(field, length, value)` triples.
  - User identity (`0x58`): `type (1) + positive_response_requested (1) + primary_len (u16) + primary +
    secondary_len (u16) + secondary`.
- Max-PDU is a u32 in the user information item; do not clamp the engine's framing limit to the u16 range
  used by sub-item lengths.

### 11.3 DIMSE

- The command set is **always** Implicit VR Little Endian, independent of the dataset syntax.
- In the command field, bit 15 marks a response; a response's command field is the request value plus
  `0x8000`.
- An unrecognised command field must answer Processing Failure or send A-ABORT — **never panic**.
- N-service requests use `Requested*` fields, not `Affected*`.
- `Priority`: Low = 2, Medium = 0, High = 1; the default is Medium.

### 11.4 Server and client

- The server implements `ServiceProvider`; every operation has a default that refuses, so a provider opts
  in only to what it serves. The trait is an `async_trait`.
- The client negotiates presentation contexts on the first request and **must renegotiate when switching
  SOP class**.
- Reverse C-STORE (C-GET / C-MOVE) requires role selection; register a handler with
  `with_reverse_store_handler` or `collect_reverse_stores`.
- Sub-operation counters must be populated from the actual results. Returning a defaulted summary makes a
  failed C-MOVE report success.
- `max_clients` must actually be enforced (a semaphore or equivalent); a config field that no code path
  reads is a bug. The same applies to `association_timeout` on the server side.

## 12. Serialization, Media, SR, Printing, Anonymization

### 12.1 DICOM JSON (JSON-01/02)

- Tag keys are 8 hex digits `GGGGEEEE`.
- A value lives in exactly one of `Value` (array), `InlineBinary` (base64) or `BulkDataURI`.
- PN uses the three groups (Alphabetic / Ideographic / Phonetic).
- Numeric mode is configurable (AsNumber / AsString / PreferablyAsNumber); DS keeps trailing zeros.
- **Group length elements `(gggg,0000)` must be stripped.** Emitting them is a known defect (§15).
- The reader tolerates attribute order and unknown attributes.

### 12.2 Media (DICOMDIR, MEDIA-01..03)

- Offsets in DICOMDIR are **absolute byte offsets from the first byte of the file**, including preamble,
  `DICM` and file meta.
- **Record item offsets must come from the write process itself**, not from scanning for trailing
  `FFFE,E000` headers. A record containing an embedded sequence (an icon, for instance) makes the scan
  return the wrong item — a PATIENT record would be mistaken for a STUDY.
- `add_file` deduplicates through Patient → Study → Series → Instance, reusing nodes by UID.

### 12.3 Structured Reports (SR-01/02)

- There are 15 SR value types (including `SCOORD3D`) and 7 relationship types.
- A code item has **no short/long tag family pair**. The value slot is chosen by length or by URN:
  `CodeValue (0008,0100, SH)`, `LongCodeValue (0008,0119, UC)`, `URNCodeValue (0008,0120, UR)`. Scheme,
  meaning and version are `(0008,0102)`, `(0008,0104)` and `(0008,0103)`.
- Content items form a tree; preserve it.

### 12.4 Printing (PRINT-01/02)

- Film Session / Film Box / Image Box / Presentation LUT are dataset-backed models.
- Layout rendering reuses the render pipeline (EmptyImageDensity background, Trim border, per-cell
  aspect-fit, Polarity REVERSE).
- Verify every tag against PS3.3 before use: `(2010,0120)` is MinDensity, and `(2010,0500)` is
  ReferencedFilmSessionSequence (`(2010,0510` is ReferencedImageBoxSequence).

### 12.5 Anonymization (ANON-01)

- The PS3.15 profile is driven by a CSV table whose contents match fo-dicom's DefaultProfile.
- Actions: `X` remove, `Z` zero-length, `D` replace with dummy, `U` replace with a new UID, `K` keep,
  `C` clean.
- UID replacement must stay consistent **within one anonymizer instance**, otherwise references break.
- Recurse into sequences; an `X` action removes the whole sequence, not just its children.
- The `D` action must respect VR: numeric-string VRs (DS/IS) get a valid number such as `"0"`, never the
  word `ANONYMOUS`.

## 13. Error Model

- Every public API returns `Result<T, Error>`; `Error` is an enum (`Data`, `Reader`, `File`, `Codec`,
  `Validation`, `Imaging`, `Network`).
- **Never panic** on any input, including peer-controlled network data.
- Parse errors must carry position information (`ReaderError::Eof { position, needed }`) so malformed
  files can be located.
- Write path errors and read path errors stay distinguishable, because only the read path is tolerant.

## 15. Known Deviations (do not copy these; fix them when you touch the area)

These were design intent but the implementation does not match. Do not treat them as current contracts.

- **JSON does not strip group lengths** — `(gggg,0000)` keys are still emitted.
- **`ISO_IR 109/110/126/127/138/144/148/166` map to Windows code pages** instead of ISO-8859-x / TIS-620.
  A `charset.rs` unit test asserts the wrong mapping and must be corrected with the fix.
- **Private-tag VRs are always `UN`** — `dictionary_vr` never consults the private dictionary.
- **CP-246 condition is inverted** — it switches to little endian only for private tags; the standard
  requires non-private.
- **The fragment-sequence `FFFE,E0DD` branch does not consume its length field**, desynchronising the
  rest of the stream.
- **`Suspended` / `IsPartial` are not implemented**, so a truncated file can only fail wholesale.
- **Private-sequence probing (`IsPrivateSequence` / `IsPrivateSequenceBad`) is not implemented.**
- **`LongCodeValue` / `URNCodeValue` are not implemented** — long and URN values are written into
  `CodeValue`.
- **`store.rs` defaults to `SpoolToTemp` and leaks temp files**; the default should not leave files
  behind.

### 15.1 Deferred API limitations

The 2026-10-29 code review (`target/2026-10-29-code-review.md`) raised three interface issues that are
**not behavioural bugs**. They were deliberately left out of that review's fix batch because each one is
an API-breaking change or a cross-module redesign, and must land with its own compatibility decision
rather than be folded into a correctness commit.

1. **`DicomImage` geometry accessors are infallible but return `Result`**
   (`crates/radicom/src/render/mod.rs`, `width` / `height` / `number_of_frames` / `is_grayscale`).
   They only wrap a cached field and never fail. They should return `u32` / `bool` and drop the `Result`
   wrapper; that is a public API break, so it needs a version decision. Note that `RawImage` (same
   module) already exposes the infallible shape, so `DicomImage` should follow it.
2. **`PixelDataConverter` is a C#-style namespace class** (`crates/radicom/src/render/pixel_converter.rs`).
   It is stateless and holds a single `reverse_bits` static; a plain module function is the Rust shape.
   Pure cleanup with no behaviour change — safe to do on its own, but it renames a public item.
3. **Deferred-I/O buffers panic instead of reporting an error** (`crates/radicom/src/model/buffer.rs`,
   `FileWindow` around line 608/613 and `StreamWindow` around line 716). `ByteBuffer::data` cannot
   return an I/O error, so a read failure on a lazily-loaded value becomes `expect(...)` / a panic
   rather than a typed error. Fixing this means making the buffer read path fallible across every
   caller, which contradicts the no-panic guarantee stated in
   [02-development-guide.md](02-development-guide.md) §5.1 until it is done. Until then, treat
   `ByteBuffer::data` as an infallible accessor only for values already materialised in memory.
