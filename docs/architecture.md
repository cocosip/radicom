# Architecture and Core Contracts

> This is the **only design reference** when changing code. It records the invariants and design
> decisions you must not violate — it does not restate the implementation, which is the source of truth.
> Testing, interop and release procedures live in [development-guide.md](development-guide.md).

## 0. Workspace and Dependency Direction

| Crate | Responsibility |
|---|---|
| `radicom` | Core library: data model, file IO, pixel, render, print, media, SR, anonymization, codec **interfaces** |
| `radicom-network` | tokio-based network layer: PDU, association, DIMSE C-/N-services, SCU/SCP, TLS |
| `radicom-json` | DICOM JSON (PS3.18) and Native XML |
| `radicom-dict` | Generated tag/UID/private dictionary tables from the pinned fo-dicom dictionary XML |

Dependencies flow one way: `radicom` depends on none of the other three; `radicom-network` and
`radicom-json` depend on `radicom`; `radicom-dict` is used only by `radicom`. Lower layers must never
depend on higher ones.

Design principles:

1. **fo-dicom semantics, Rust-idiomatic API** — do not copy the C# shape (no DI container, no inheritance
   hierarchies). Express the same capabilities with traits, generics and ownership.
2. **Zero-copy first** — large values (pixel data, big OW/OB) are always buffer references; uncompressed
   frames are slice views; strings and numbers evaluate lazily.
3. **Parsing decoupled from building** — the reader emits observer events only; dataset building,
   DICOMDIR stitching, SR, dump and JSON all reuse the same parser.
4. **Codecs fully decoupled from the core** — the core has zero compression-library dependencies; codecs
   are injected through a trait plus registry.
5. **Synchronous core, async network** — the data model and IO are synchronous (FFI-friendly, easy to
   test); the network layer is fully async.
6. **Lenient reading, strict writing** — the read path tolerates malformed data (T1–T10); the write path
   guarantees standard compliance.

## 1. Tag

### 1.1 Representation

```rust
pub struct Tag { group: u16, element: u16, private_creator: Option<Arc<PrivateCreator>> }
```

- `is_private()` is true for odd groups.
- Conversions to/from `u32` pack as `(group << 16) | element`.
- Constant `Tag::UNKNOWN` is `(FFFF,FFFF)`.

### 1.2 Equality and ordering (critical — dataset storage order depends on it)

| Comparison | Rule |
|---|---|
| Both public | compare `group`, then `element` |
| Both private, same group | compare `group`, then the **full `element`**, then the creator string |
| Anything else | compare `group`, then `element`, then the creator string |

`Hash` follows the same fields: `group`, full `element`, then the creator string.

**Do not "clean this up".** Comparing the low 8 bits alone would make `(gggg,1101:C)` and
`(gggg,1201:C)` compare equal, so one private block could overwrite another. The full-element rule
matches fo-dicom `DicomTag.CompareTo` (group → element → creator) and keeps serialized byte order
stable; changing it changes the byte order of serialized datasets.

### 1.3 String formats

| Format | Example | Used by |
|---|---|---|
| General `(GGGG,EEEE)` / `(GGGG,EEEE:CREATOR)` | `(0028,0010)` | Display / parse default |
| No parentheses | `0028,0010` | Parse accepts |
| JSON `GGGGEEEE` (8 hex digits) | `00280010` | DICOM JSON |
| Masked | `(60xx,4000)` | `MaskedTag` only |

Parse failures return `Error::Data` carrying the offending input. Creator strings are interned through
the dictionary's creator cache.

### 1.4 Masked tags (TAG-05)

`MaskedTag { card: u32, mask: u32 }`. `parse("(60xx,4000)")` maps each hex nibble to `0xF` in the mask
and each `x` to `0x0`; `is_match(tag)` is `(tag.to_u32() & mask) == card`; display re-derives the `x`
positions from the mask. Consumers: repeating overlay groups, anonymizer wildcard rules, masked
dictionary entries.

## 2. VR, UID, Transfer Syntax, Dictionary

- **VR** — the 34 standard value representations. Metadata drives encoding: `is_16bit_length()` decides the
  explicit-VR length field width, `unit_size()` drives byte swapping and scalar reads, plus string /
  charset-sensitivity / multi-value predicates. Validation rules are in §5.
- **UID** — `Uid` holds an `Arc<str>` interned through a global registry. `Uid::parse` never fails (an
  unknown UID keeps its literal value); `query` returns `Option`. Private UIDs can be registered.
  `Uid::generate` produces `2.25.<decimal uuid>` UIDs; `UidGenerator` performs consistent remapping (the
  same source UID always maps to the same replacement).
- **Transfer syntax** — `TransferSyntax` records the UID, endianness, VR explicitness, and whether the
  pixel data is encapsulated/compressed. `syntaxes::*` holds the built-ins; `TransferSyntax::register` is
  the extension point used by application-defined syntaxes and by `radicom-codecs`.
- **Dictionary** — the public and private dictionaries are generated by `radicom-dict` and **must never be
  hand-maintained**. Private-tag VRs must be looked up in the private dictionary (located by creator
  block); returning `UN` for every private tag is a defect, not a design choice.

### 2.1 Naming

Constants are named after the **PS3.6 keyword** in SCREAMING_SNAKE_CASE, matching fo-dicom one-to-one
(`DicomTag.PatientName` ↔ `Tag::PATIENT_NAME`, `DicomUID.CTImageStorage` ↔
`uids::CT_IMAGE_STORAGE`). Do not add a second **string literal** for the same value — that is a second
thing to keep in sync. A thin local re-export that binds to the generated constant
(`pub const VERIFICATION: &str = radicom::uids::VERIFICATION;`) is fine: it is one definition with a
shorter name at the point of use, not a second source of truth.

Use the constants at every call site:

```rust
use radicom::{syntaxes, uids, Tag};

ds.insert_value(Tag::PATIENT_NAME, "Doe^John");
ds.insert_value(Tag::SOP_CLASS_UID, uids::CT_IMAGE_STORAGE);
ds.set_transfer_syntax(syntaxes::EXPLICIT_VR_LITTLE_ENDIAN.clone());
```

Never write `Tag::new(0x0010, 0x0010)` or a UID literal. The constants are generated from the dictionary,
so they cannot drift from it. (A raw `(group, element)` pair in an ad-hoc query-builder convenience —
`CFindRequest::with_key` — is discouraged in favour of `with_tag(Tag, Vr, ..)` for the same reason.)

## 3. Dataset and Elements

- **Storage** — `BTreeMap<Tag, DicomItem>`. Iteration order *is* tag-ascending order and the writer
  depends on it. Switching to `HashMap` would break byte-level round-trips.
- **`normalize_read`** — reading a private tag resolves it to its real address inside the creator block.
  **Every read path must go through it**; querying the underlying map directly misses private elements.
- **Zero-copy large values** — `ElementValue::as_buffer()` returns `Arc<dyn ByteBuffer>` which may be a
  `MemoryBuffer`, a `FileWindow` (a region on disk) or a `BulkDataUri`. **Never assume it is in memory**;
  call `data()` only when you actually need the bytes, because that materialises them.
- **Numeric reads** — the integer and float `FromElement` impls accept both string VRs (IS/DS parsing) and
  binary VRs. A binary read advances at the **VR's own `unit_size()`** and widens/sign-extends to the
  requested type, so `u32` from `US` and `f64` from `US` both work, at any index.
  **Do not reintroduce `unit_size().max(T::SIZE)`.** That strides by the destination width, reads past the
  element and silently yields 0 — the exact root cause of Rows/Columns reading as 0 on real files (and
  therefore of `get_frame` returning empty frames).
- **`insert_value` VR resolution** — the **dictionary VR is authoritative**. A numeric value's own
  preference (`IS` for integers, `DS` for floats) is only a hint and is replaced by the dictionary VR
  whenever both are numeric: `Tag::ROWS` → `US`, `Tag::NUMBER_OF_FRAMES` → `IS`,
  `Tag::RESCALE_INTERCEPT` → `DS`. A non-numeric hint (a string written to a binary tag) keeps the
  caller's choice, because that value cannot be silently re-encoded. Without this rule
  `insert_value(Tag::ROWS, 512u16)` wrote an `IS` string — non-conformant bytes that round-tripped only
  because the reader made the same mistake.

## 4. Character Sets (ENC-01..04)

- Driven by `(0008,0005) Specific Character Set`, including ISO 2022 escape-sequence switching and
  multi-byte encodings.
- Decoded values are always UTF-8.
- A `SpecificCharacterSet` list with an empty leading term resolves to its first non-empty term
  (`\ISO 2022 IR 58` → GBK, `\ISO 2022 IR 87` → ISO-2022-JP).
- **Single-byte `ISO_IR nnn` terms must map to the corresponding ISO-8859-x**, never to a Windows code
  page: `ISO_IR 109/110/126/127/138/144/148` map to `iso-8859-3/4/7/6/8/5/9`. The exception is
  `ISO_IR 166`, which maps to `windows-874` — the WHATWG alias of TIS-620, and a superset of it.
- An unrecognized term falls back to `windows-1252` (never fails to decode); `is_known_charset`
  exposes the detection so a caller can report the fallback.

## 5. Validation (VAL-01..03)

- Validation can be disabled globally, per scope (`ValidationScopeGuard`) or per dataset.
- A failure returns `ValidationFailure`, strictly distinct from a parse error: **validation may be
  skipped, parsing may not**.
- `Dataset::validate()` is on demand, like fo-dicom's `Validate()`. The writer and parser deliberately do
  **not** call it, so tolerant real-world round-trips keep working.
- The strict validators follow the VR grammar, not the tolerant parsers: TM accepts only
  `HH[MM[SS[.F{1,6}]]]` (no ACR-NEMA `HH:MM:SS`/`HH.MM.SS`) and DT only
  `YYYY[MM[DD[HH[MM[SS[.F{1,6}]]]]]]` with an `&ZZXX` offset (no bare `±HHMM`, no dotted dates).
  Control characters below 0x20 (except the allowed escapes) and DEL (0x7F) are rejected in text VRs.
- VM checks honour the multiplicity step: `2-2n` requires an even value count, `3-3n` a multiple of three.
- Every value of Specific Character Set (0008,0005) must be a term the charset registry knows (PS3.5
  §6.1.1); a zero-length first value means the default repertoire.

## 6. Buffers and IO (BUF / IO)

- The `ByteBuffer` trait separates `size()` from `data()`: `size()` must be cheap and must not
  materialise, `data()` may.
- **Reads are fallible.** `data()` returns `io::Result<Cow<'_, [u8]>>` and
  `get_byte_range(offset, buf)` returns `io::Result<()>`; an out-of-bounds range is
  `ErrorKind::InvalidInput`, not an assertion. Callers on the parse, write and pixel paths must propagate
  the error. The fallible form is the only form.
- `as_slice()` is the zero-copy fast path for a value that is already contiguous in memory, and returns
  `None` otherwise. `copy_to()` keeps its signature and streams a value out without materialising it.
- **`FileWindow` is a region on disk, not loaded content.** Any path that promises not to read large
  values must not call `data()`. A failed read from a `FileWindow` or a `StreamWindow` (the temp-file
  spill) returns a real `io::Error` instead of panicking; the `StreamWindow` spill error is sticky,
  because the source is consumed and cannot be retried.
- Byte sources and targets are generic over `Read + Seek` / `Write`, so memory and files share one
  parser implementation.
- Async code must not perform blocking file IO on a runtime worker thread; use `spawn_blocking`.

## 7. Reader (RD-01..05) and Tolerance Rules T1–T10

The reader emits observer events and does not build datasets directly. The recursion depth cap defaults
to 256.

Lenient reading is a core acceptance criterion, not a nicety:

| Rule | Situation | Handling |
|---|---|---|
| T1 | Explicit VR bytes are two spaces | use the dictionary VR, stay explicit |
| T2 | Explicit VR is garbage | rewind, parse that element as implicit |
| T3 | UN with undefined length (in any transfer syntax) | parse as a sequence whose items are Implicit VR Little Endian (PS3.5 §6.2.2, CP-246). A *defined*-length UN the dictionary calls SQ is probed for item shape and stays UN bytes when the value is not item-shaped |
| T4 | Private SQ encoded explicitly inside an implicit dataset (and the inverse) | probe, then switch mode for the subtree |
| T5 | Orphan item tag | implicit undefined-length SQ |
| T6 | Fragment sequence missing its final delimiter at EOF | accept (fo-dicom #1339) |
| T7 | SQ ends directly with a sequence delimiter where an item was expected (k-pacs style) | accept |
| T8 | Trailing garbage after the dataset | ignore |
| T9 | Group length element with VR UN | treat as UL |
| T10 | Deflated syntax | transparently decompress |

**CP-246 condition**: a `UN` with *defined* length that is **not private** is read as a sequence whose
inner content is little endian even when the outer syntax is big endian. Inverting this condition makes
big-endian UN sequences read the wrong length. The same *item-shape probe* the private path uses is
applied first: a defined-length non-private `UN` whose content does not start with an item or sequence
delimiter is kept as raw `UN` rather than parsed as implicit elements inside a bounded window.

A fragment sequence's `FFFE,E0DD` item delimiter **must consume its 4-byte length field**, exactly like
the `FFFE,E000` item branch does. Breaking out without consuming it desynchronises the stream for every
remaining element.

## 8. Writer (WR-01..03)

- Strict output: group lengths, padding and length rules must be compliant.
- Sequences and items may be defined or undefined length, chosen by `WriteOptions`.
- Numeric values are byte-swapped to the target syntax; chunk boundaries must respect unit alignment.
- The file meta group always recalculates `(0002,0000) FileMetaInformationGroupLength` (Type 1),
  regardless of the dataset-level group-length option.
- File meta identifies the implementation with the fixed class UID (`0002,0012`) and the derived
  `RADICOM <workspace version>` name (`0002,0013`); association user information advertises the same
  version name. The name derives from `CARGO_PKG_VERSION`, and a compile-time check enforces the
  16-byte SH limit.
- ACR-NEMA format is rejected on save.

## 9. Pixel Data and the Codec Boundary (PIX / CODEC / TR)

### 9.1 This is the normative interface contract for the outside world

Changing it breaks `radicom-codecs`.

- `PixelData` is the **single** read/write gate for pixel data. Codecs, the transcoder and the renderer
  must all go through it; nothing may touch `(7FE0,0010)` directly.
- Pixel Data VR is the core's decision, never the codec's: encapsulated output is `OB` regardless of
  Bits Allocated (PS3.5 §8.2), native output is `OW` above 8 bits. `PixelDataVrMode::Compatible`
  preserves fo-dicom 5.x's legacy `OW` fragments for byte-identical output. Codecs only append frames;
  a codec that rebuilds the fragment sequence to change its VR is wrong.
- Read and write VR policy are separate. The transcoder reads tolerantly by default (`Compatible`):
  a legacy `OW` encapsulated element is accepted and preserved. `with_pixel_data_read_mode(Standard)`
  opts into input validation; output is `Standard` (`OB`) unless a compatibility mode is selected.
  `with_strict_dicom_vr(bool)` is a go-dicom-style alias for the **write** mode only, never a read
  switch.
- A `Codec` implementation must:
  - touch the dataset only through `PixelData` property setters, never other elements;
  - map every failure to `Error::Codec` and **never panic**;
  - not consume the input buffer when it does not decode (the buffer may be reused);
  - tolerate upper/lower case bit differences in the DICOM tag name when the underlying file is
    noncompliant (DICOM tag names are case-sensitive).
- This repository ships **zero built-in codecs** (divergence D10). The `pixel::codec` traits and registry
  are the frozen boundary that `radicom-codecs` implements.
- `Transcoder` selects a codec from the registry by transfer syntax. When none is registered it returns
  `Error::Codec`; it must **never fall back to pretending success**.
- Frame-size math must handle 1-bit packing, YBR 4:2:2 and 4:2:0 chroma subsampling, and multi-frame
  slicing. Single-bit samples pack **continuously** across row boundaries (PS3.5 Annex D), so one frame
  is `ceil(rows * columns * samples / 8)` bytes — not `rows * ceil(columns / 8)`. Multi-frame 1-bit data
  is continuous across *frames* too (PS3.5 §8.1.1 Note 2): frame `n` starts at bit
  `n * rows * columns * samples` and may begin mid-byte, so `native_frame` re-aligns it and `add_frame`
  ORs it into the shared byte. A zero-sized frame is an error, not an empty success.
- 4:2:2 frame size follows the standard formula `Rows * Columns * 2 * bytes` (no column rounding); the
  4:2:0 padded-plane model (`2 * ceil(Columns/2) * Rows`) exists only because 4:2:0 is encapsulated-only
  and the renderer uses padded planes.
- In-memory pixel/element buffers are **host byte order**: reads use `from_ne_bytes` and writes
  `to_ne_bytes`; only `EndianBuffer::data()` swaps for a big-endian file.

### 9.2 Photometric interpretation and LUTs

- Photometric Interpretation dispatches to the correct conversion path; dispatch on the interpretation,
  **not** on samples-per-pixel (palette is single-sample but must use the palette path).
- Fixed stage order: Modality LUT → VOI LUT (window or LUT sequence) → Presentation LUT → color
  conversion.
- A 16-bit VOI LUT output range is `0..2^n-1` and must be rescaled to that range — **not** shifted right
  by 8.
- LUT descriptors (entry count, first mapped value, VR, signedness) must be validated. Entry count `0`
  means 65536. Values outside the table clamp to the nearest endpoint.
- XA/XRF display skips the modality LUT (Clunie guidance).

## 10. Rendering (REND-01..11)

- Entry points are `render_frame(&Dataset, frame)` and `DicomImage`, both producing `RawImage`.
- `GrayscaleRenderOptions` decides where the window comes from, matching fo-dicom `FromDataset`: an
  explicit `from_window_level` choice wins; otherwise a VOI LUT Sequence `(0028,3010)`, when usable,
  takes precedence (its own window is then unused); else top-level Window Center/Width, then the
  per-frame functional-group window `(0028,9132)`, then Smallest/Largest Image Pixel Value, then a
  decoded-frame min/max. `from_histogram` and `from_bit_range` are explicit factories, not part of the
  dataset chain.
- Stored values must be normalised to the low `bits_stored` bits (drop high-bit padding) **before**
  windowing. Every raw-pixel reader — grayscale, RGB, YBR, palette, MPR, icon — must do this; skipping it
  is how 12-bit-in-16 data renders wrong.
- Window values may live in `DS` (text) or `US`/`SS` (binary) attributes, so read a numeric attribute
  numerically first and fall back to text — never text-only.
- Output scaling, spatial transforms (scale/rotate/flip/pan) and MPR reconstruction are separate
  operators applied in that order.
- Export is `RawImage` plus hand-written PNG/BMP encoders; there is no external image dependency.
- Rendering failures must return an error, never silently produce a blank image.

## 11. Networking (NET / SRV / CLI / DIMSE)

### 11.1 Layering and task model

Transport (TCP/TLS) → PDU framing → association negotiation → protocol engine → DIMSE services →
client/server. One tokio task per association. Locks must not be held across `.await`.

### 11.2 PDU and association

- A PDU header is fixed 6 bytes: type (1) + reserved (1) + length (u32, big endian).
  The negotiated Maximum Length applies to the P-DATA variable field (body); it excludes this header.
- Sub-item headers are `type (1) + reserved (1) + length (u16)` — 4 bytes, big endian. Only the P-DATA
  PDV length is 32-bit.
- UL items use exact byte lengths, without dataset-style even padding. UID values are not NUL-padded.
- Protocol Version is a bit field: bit 0 must be set; other bits are ignored. AC AE-title fields are
  reserved and are not validated against the request.
- An A-ASSOCIATE-RJ body is `reserved (1) + result (1) + source (1) + reason (1)`.
- Presentation context layout is uniform: `id (1) + reserved (1) + result (1) + reserved (1)`. The RQ
  writes result = 0; only the AC carries a real result. **Writing the result at offset 1 instead of 2
  turns every rejection into an acceptance in both directions.**
- A C-STORE dataset is streamed, not buffered: `message::write_message_streamed` runs the writer on a
  blocking thread into a bounded channel that the association task writes out. Peak memory is O(max_pdu
  + `large_object_size` + a couple of PDUs), independent of the instance size. Both the SCU C-STORE and
  the C-MOVE push and C-GET reverse-store push use it; a transcoded store still materialises its output,
  which is inherent. Each streamed PDU carries one PDV; the final PDV ("last" bit) is only known at the
  end, so the tail is held back until the writer finishes. A failure mid-stream sends A-ABORT, so the
  association must be dropped afterwards.
- An A-ASSOCIATE-AC carries `result` plus **one** transfer syntax per context, including rejected
  contexts (where its value is ignored). It carries no abstract syntax; the client refills it from
  its RQ by context id. A peer that echoes a redundant abstract syntax is tolerated (it is ignored), and
  a peer may answer only the contexts it accepted.
- User-information sub-items:
  - Role selection (`0x54`): `uid_len (u16) + uid + scu (1) + scp (1)`.
    Roles describe the association requestor; without a selection for a SOP class, the requestor
    acts as SCU and the acceptor as SCP.
  - Extended negotiation (`0x56`): the application information is a **flat byte array** where the index is
    the field number — not `(field, length, value)` triples.
  - Common extended negotiation (`0x57`): SOP Class UID, Service Class UID, then a u16 total length
    and length-prefixed related general SOP Class UIDs; an empty related list is valid.
    `common_extended` is a `Vec<CommonExtended>`; each entry names its `sop_class_uid`.
  - Storage application information has six bytes: fields 1/3/5, reserved bytes 2/4/6.
    Retrieve enhanced-multiframe conversion uses field 2.
  - User identity (`0x58`): `type (1) + positive_response_requested (1) + primary_len (u16) + primary +
    secondary_len (u16) + secondary`.
- Max-PDU is a u32 in the user information item; do not clamp the engine's framing limit to the u16 range
  used by sub-item lengths.
- The receive side caps one PDU at 256 KiB (`pdu::MAX_PDU_SIZE`). A configured `max_pdu_length` above it
  is advertised clamped to that same ceiling, so the value we announce and the value we accept agree;
  a peer that sends more is a protocol error.
- A well-formed but unsupported context set is answered with A-ASSOCIATE-RJ (source user, reason 1);
  a structurally malformed one (bad context ID, empty abstract syntax, no contexts) is answered with
  A-ABORT, because no rejection reason describes it. Both are deliberate.

### 11.3 DIMSE

- The command set is **always** Implicit VR Little Endian, independent of the dataset syntax.
- In the command field, bit 15 marks a response; a response's command field is the request value plus
  `0x8000`.
- An unrecognised command field must answer Processing Failure or send A-ABORT — **never panic**.
- N-GET/SET/ACTION/DELETE requests use `Requested*`; N-CREATE/EVENT-REPORT use `Affected*`.
  Responses use `Affected*`, including failure responses built from a request.
- Command Data Set Type `0101H` means absent; every other value means present (including fo-dicom
  `0202H`). Message ID zero is valid on the wire and required ID fields must still be present;
  high-level request APIs reserve zero as their automatic-allocation sentinel.
- C-service response UIDs are optional. Typed response APIs represent absent UIDs as empty strings and
  omit them on encoding; correlation rejects a supplied mismatching UID.
- Pending C-GET/MOVE responses require all four sub-operation counters; terminal responses may omit
  them. N-ACTION/EVENT-REPORT replies preserve the corresponding Type ID when supplied for a reply.
- Every outstanding request ID stays registered until a terminal response; Pending never retires it.
- `Priority`: Low = 2, Medium = 0, High = 1; the default is Medium.

### 11.4 Server and client

- The server implements `ServiceProvider`; every operation has a default that refuses, so a provider opts
  in only to what it serves. The trait is an `async_trait`. Each operation also has a `*_with(request,
  &AssociationInfo)` default method that forwards to the plain form; override it to read the peer's
  calling/called AE (peer-asserted, not authenticated). `FileStoreProvider` is the built-in Storage SCP
  that writes each instance as `<sop-instance-uid>.dcm` into a directory.
- The service-class SCP initiates N-EVENT-REPORT. Without role selection the acceptor is SCP by default;
  the sender is gated by the same SCU-role predicate the receiver validates with, and a report with no
  registered handler is answered `Unrecognized Operation` rather than left unacknowledged.
- A Modality Worklist C-FIND is built from the Scheduled Procedure Step Sequence (§K.6.1.2.2), not from a
  Query/Retrieve Level; a strict MWL SCP rejects a stray `(0008,0052)`.
- The client negotiates presentation contexts on the first request and **must renegotiate when switching
  SOP class**. `DicomClient::association()` exposes the open association for inspection.
- Concrete request objects (`CEchoRequest`, `CStoreRequest`, `CFindRequest`, `CGetRequest`,
  `CMoveRequest`, and `NServiceRequest`) convert into `DicomRequest` and can be passed together to
  `DicomClient::send_requests` for mixed C-ECHO, C-STORE, C-FIND, C-GET, C-MOVE and N-service traffic.
  The optional `DicomRequestQueue` builder and `send_queue` wrapper use the same path. The client
  negotiates the union of contexts and role selections once, limits in-flight requests by the
  asynchronous-operations window, and routes callback events by Message ID; `send_batch` and the
  existing typed send methods remain compatibility convenience APIs with typed return values.
  C-GET drains earlier requests and blocks later admissions until completion, allowing reverse C-STORE
  traffic without competing streamed writes. Each distinct source storage syntax has its own context;
  mixed requests support cancellation by active Message ID. A C-CANCEL that arrives before the request's
  dataset (so no cancel slot exists yet) is remembered and applied when the slot is registered.
- Reverse C-STORE on a C-GET association requires role selection; register a handler with
  `with_reverse_store_handler` or `collect_reverse_stores` and declare its storage SOP classes.
  C-MOVE delivers C-STORE on a separate association to the configured destination AE.
- Received bodies obey configured limits even below the spool threshold; deflated output has the same
  hard limit on both memory and spool paths. Blocking file reads and parsing run on the blocking pool. A
  dataset that cannot be decoded is answered `0xC000` (Unable to process), distinct from a resource
  shortfall (`0xA700`).
- Sub-operation counters must be populated from the actual results. Returning a defaulted summary makes a
  failed C-MOVE report success.
- `max_clients` must actually be enforced (a semaphore or equivalent); a config field that no code path
  reads is a bug. The same applies to `association_timeout` on the server side.
- TLS client trust is platform-first: with no CA bundle the client trusts the OS root store
  (`rustls-native-certs`), and a bundle pins the anchors instead of extending them. The certificate is
  verified against `server_name` when set, otherwise the peer address; `accept_any` skips verification
  and is only for tests (PS3.8 §9.3). Built server/client TLS configurations are cached per distinct
  on-disk material, so a repeated handshake does not reload PEM files or the trust store.
- Every association rejection and abort path logs a `tracing::warn!` with the reason, so a peer's
  "cannot connect" report is diagnosable.

## 12. Serialization, Media, SR, Printing, Anonymization

### 12.1 DICOM JSON (JSON-01/02)

- Tag keys are 8 hex digits `GGGGEEEE`.
- A value lives in exactly one of `Value` (array), `InlineBinary` (base64) or `BulkDataURI`.
- A deferred value (a `FileWindow`/`StreamWindow`/`TempFileSpill`) is written as `BulkDataURI` when
  `JsonOptions::bulk_data_uri` names one, and is then never materialised; otherwise it is base64-encoded.
- `BulkDataURI` is legal only for the PS3.18 F.2.2 VRs (DS, FL, FD, IS, LT, OB, OD, OF, OL, OV, OW, SL,
  SS, ST, SV, UC, UL, UN, US, UT, UV); deferring any other VR by URI is an error, never a silent drop.
- Native XML (PS3.19) carries `xml:space="preserve"` on the root and never encodes Group Length.
- PN uses the three groups (Alphabetic / Ideographic / Phonetic).
- Numeric mode is configurable (AsNumber / AsString / PreferablyAsNumber); DS keeps trailing zeros.
- **Group length elements `(gggg,0000)` must be stripped at every level of the tree.**
- The reader tolerates attribute order and unknown attributes.

### 12.2 Media (DICOMDIR, MEDIA-01..03)

- Offsets in DICOMDIR are **absolute byte offsets from the first byte of the file**, including preamble,
  `DICM` and file meta.
- **Record item offsets must come from the write process itself**, not from scanning for trailing
  `FFFE,E000` headers. A record containing an embedded sequence (an icon, for instance) makes the scan
  return the wrong item — a PATIENT record would be mistaken for a STUDY.
- `add_file` deduplicates through Patient → Study → Series → Instance, reusing nodes by UID.
- Referenced File IDs are validated, not copied: each component is 1-8 characters of `A-Z`, `0-9` or `_`
  (PS3.10 §8.2/§8.5) and a File ID has 1-8 components. A caller path such as `img.dcm` is rejected, so
  callers must map names (the scanner uppercases stems).
- A DICOMDIR is always Explicit VR Little Endian (PS3.10 §8.1); `from_bytes` normalizes the loaded dataset
  so a re-save stays conformant.

### 12.3 Structured Reports (SR-01/02)

- There are 15 SR value types (including `SCOORD3D`) and 7 relationship types.
- A code item has **no short/long tag family pair**. The value slot is chosen by length or by URN:
  `CodeValue (0008,0100, SH)`, `LongCodeValue (0008,0119, UC)`, `URNCodeValue (0008,0120, UR)`. Scheme,
  meaning and version are `(0008,0102)`, `(0008,0104)` and `(0008,0103)`.
- Content items form a tree; preserve it.
- The document dataset **is** the root content item (PS3.3 C.17.2): ValueType CONTAINER, the document
  title in ConceptNameCodeSequence and ContinuityOfContent live at the top level, and every item of the
  top-level ContentSequence is a child with a RelationshipType. `StructuredReport::set_root` hoists a
  root container into the dataset; `content_items`/`set_content_items` read and replace its children.
  A by-reference relationship target carries only (0040,DB73) and no ValueType.
- All 15 value types are buildable and readable: `ContentItem::value()` returns a `ContentValue`, and
  SCOORD/SCOORD3D/TCOORD/WAVEFORM carry their macro attributes (`GraphicData` FL pairs/triplets,
  `ReferencedFrameOfReferenceUID` for SCOORD3D, one of the three temporal reference lists, the
  waveform channels). Point counts and the closed POLYGON are checked at construction (C.18.6–C.18.9).
- `StructuredReport::validate` checks common SR document attributes (identity, instance/content date/time,
  study/series identity, Type 2 patient/study/equipment fields), completion/verification and the conditional
  verifying observers. It rechecks imported value macros, coded-entry cardinality, finite spatial/temporal
  data, reference identity and by-reference paths.
- PS3.3 C.18.1: a NUM item has a Type 2 Measured Value Sequence (zero or one item); an empty sequence is
  valid only with the Type 1C Numeric Value Qualifier Code Sequence, which explains the missing value.
- PS3.3 C.18.3/C.18.4/C.18.5: a COMPOSITE, IMAGE or WAVEFORM item carries exactly one Referenced SOP
  Sequence item, so the constructors take a single reference.
  It does not certify a clinical template (TID) or every SOP-specific relationship table.
- WAVEFORM channel pairs live inside each ReferencedSOPSequence item (C.18.5).
  `waveform_references()` preserves per-reference selections; the legacy common-channel `value()` view
  returns None for references with different selections, rather than inventing associations.

### 12.4 Printing (PRINT-01/02)

- Film Session / Film Box / Image Box / Presentation LUT are dataset-backed models.
- Layout rendering reuses the render pipeline (BorderDensity film area, EmptyImageDensity image box
  area, Trim border, per-cell aspect-fit, Polarity REVERSE, the MinDensity/MaxDensity window and the
  SmoothingType filter). All of these are Film Box attributes (Table C.13-3) read from the dataset; an
  Image Box SmoothingType overrides the film value (Table C.13-5).
- Verify every tag against PS3.3 before use: `(2010,0120)` is MinDensity, `(2010,0500)` is
  ReferencedFilmSessionSequence, and `(2010,0510)` is ReferencedImageBoxSequence.
- The Presentation LUT Descriptor is strict (PS3.3 C.11.4.1): bit depth 10-16 (never 8), first mapped value
  always 0, one sequence item, and entries stored high-aligned in 16-bit words (`value >> (16 - bits)`).

### 12.5 Anonymization (ANON-01)

- The PS3.15 profile is driven by a CSV table whose contents match fo-dicom's DefaultProfile.
- Options are a bitmask (`AnonOptions`): the Basic Profile is the baseline, a single `AnonOption`
  implies it, and for each CSV row the highest enabled column with a non-empty cell wins while the
  first matching row wins (fo-dicom `LoadProfile` + `FirstOrDefault`). `AnonOptions::bit(..)` requests
  one column without the baseline, which is what fo-dicom's options-only calls do.
- Actions: `X` remove, `Z` zero-length, `D` replace with dummy, `U` replace with a new UID, `K` keep,
  `C` clean.
- UID replacement must stay consistent **within one anonymizer instance**, otherwise references break.
- Recurse into sequences; an `X` action removes the whole sequence, not just its children.
- The `D` action must respect VR: numeric-string VRs (DS/IS) get a valid number such as `"0"`, never the
  word `ANONYMOUS`.
- De-identification is declared, not implied (PS3.15 E.1.1): `anonymize_in_place` sets
  PatientIdentityRemoved `(0012,0062)` = `YES` and DeidentificationMethod `(0012,0063)`.
  `anonymize_file_in_place` syncs MediaStorageSOPInstanceUID with the anonymized dataset and drops the
  identifying file-meta entries (source/sending/receiving AE titles, private information), which the writer
  replaces with radicom's own implementation description on save.

## 13. Error Model

- Every public API returns `Result<T, Error>`; `Error` is an enum (`Data`, `Reader`, `File`, `Codec`,
  `Validation`, `Imaging`, `Network`).
- **Never panic** on any input, including peer-controlled network data. For buffer reads this is
  structurally enforced: `ByteBuffer::data()` and `get_byte_range()` return `io::Result`, so a failed read
  of a deferred value is a typed error rather than a panic.
- Parse errors must carry position information (`ReaderError::Eof { position, needed }`) so malformed
  files can be located.
- Write path errors and read path errors stay distinguishable, because only the read path is tolerant.

## 14. Intentional Divergences from fo-dicom (not defects)

| ID | Divergence | Reason |
|---|---|---|
| D7 | Four .NET image backends collapse into one `RawImage` plus an optional backend | no equivalent platform bindings in Rust |
| D10 | No built-in codecs; `radicom-codecs` provides them | mirrors `FO-DICOM.Core` ↔ `fo-dicom.Codecs` |
| D11 | No second JSON backend | serde covers it |
| D12 | No `opentelemetry` dependency; `tracing` field conventions instead | avoid an extra dependency |
| D13 | JSON `NumberMode::default()` is `PreferablyAsNumber`, not fo-dicom's `AsNumber` | fo-dicom writes `1` for `"0001"` and loses the stored text; `AsNumber` reproduces it when byte compatibility is required |
| D14 | The two retired MIME/XML transfer syntaxes keep `is_retired = true` | fo-dicom's transfer-syntax initializers omit the flag its own UID dictionary sets |
| D15 | A streamed C-STORE sends one PDV per P-DATA PDU instead of one buffered dataset | peak memory stays O(max-PDU); the reassembled message is identical, only framing differs |
| D16 | A deferred buffer is written as JSON `BulkDataURI` only when `JsonOptions::bulk_data_uri` names one | naming a URI means hosting the bytes, which is the caller's job; the default stays byte-compatible with fo-dicom |
| D17 | Anonymizer selection is the `AnonOptions` bitmask; a single `AnonOption` implies `BasicProfile \| it` | matches fo-dicom's `[Flags]` options and its CSV merge order; a single exclusive column would leave PHI in place |

## 15. Known Deviations (do not copy these; fix them when you touch the area)

There are **no open deviations**: the implementation matches the intended design recorded in this
document. Record any deviation found later here — as a defect, not a contract — instead of letting it be
mistaken for current behaviour to copy.

Two behaviours are occasionally reported as defects but are deliberate, so they are not open deviations:
buffer reads are fallible (see §6) and the receive side caps one PDU at 256 KiB (§11.2). The
defined-length non-private `UN` tolerance and its item-shape probe are specified in §7 ("CP-246
condition").
