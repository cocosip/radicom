# Code Review — 2026-10-29

A full read-through of the workspace against **fo-dicom 6.0.0-alpha1** (source read locally) and the
DICOM standard (PS3.3/3.5/3.6/3.7/3.8/3.10/3.15/3.18), then fixes, regression tests, a coverage
floor, and benchmarks. Image codec implementations (`radicom-codecs`) are out of scope by design.

## Method

- Three independent reviewers walked disjoint areas (core model/IO/encoding/validation,
  `radicom-network`, and pixel/render/print/media/SR/anonymizer/rules/json) plus a Lead pass over the
  final diff. Every finding was confirmed by reading the real flow and, where practical, by a probe
  test before fixing.
- Finding IDs were tracked in `CORE-*`, `NET-*`, `FEAT-*` and classified P0–P3. **1 P0, 18 P1 and the
  majority of P2 defects were fixed**; every fix has a regression test that fails on the old code. The
  remainder (mostly P3 cleanups and new-feature requests) is listed under "Deliberately deferred".
- No test was weakened. Wire-format goldens were changed only where the old bytes violated PS3.8
  (the P-DATA maximum was body-only). No new dependency was added; no fo-dicom-shaped abstraction was
  introduced.
- The coverage metric is **production lines only**: test/bench/example targets and inline
  `#[cfg(test)]` modules are excluded (`cargo xtask coverage`), because a per-module test count is
  easy to inflate.

## Verdict by axis

| Axis | Result |
|---|---|
| 1. Functional parity with fo-dicom | P0/P1/P2 surface complete. The review still found real gaps behind "DONE" claims — wrong functional-group tags, missing FileMetaInformationVersion, dropped ISO 2022 designators, the Icon Image Sequence tag, multi-fragment single-frame pixel data, an SR anonymization PHI leak, and network wire mismatches — all fixed. Remaining: codecs (separate project), macOS MAC, real-peer interop. |
| 2. Idiomatic Rust | No C# translation layer, no single-implementation traits, no plugin scaffolding. The review **removed** a needless `Option` layer (`attribute_to_item`), dead branches (`text_form`, `PduSplitter::split_bytes`), and duplicated command encoding. Clippy `-D warnings` is clean across all targets. |
| 3. Performance | Undefined-length writes no longer re-walk each subtree; `read_file_meta` reads the header + group 0002 only; multi-value splits are O(n); P-DATA is sent in one vectored write per message (no flush per PDU); the command set is encoded once; the transcoder is cached per association/CMOVE batch; grayscale render reads row slices / `as_chunks::<2>` instead of per-pixel `Option`s, and 512² frames stay on one thread. |
| 4. Tests and coverage | 1,060 → **1,313 tests** (1 ignored); production line coverage 88.95% → **95.98%** (core 96.01%, json 97.12%, network 95.75%). The 95% floor is enforced by `cargo xtask coverage` and a CI job. |
| 5. Benchmarks | Existing `core.rs` + `throughput.rs` extended by `crates/radicom/benches/workflows.rs`: charset UTF-8 and ISO 2022 encode/decode, deflate, uncompressed transcode, validation, DICOMDIR build/save, directory scan, on-demand vs `ReadAll` open, anonymization. |
| 6. DICOM conformance | ISO 2022 designators are emitted and re-emitted after delimiters (byte-checked against `chrGB2312.dcm`); functional-group tags follow PS3.6; saved files always carry `(0002,0001)=00\01` (PS3.10); the negotiated PDU maximum now covers the whole frame (PS3.8); A-ASSOCIATE-RQ context/version/application-context validation rejects correctly; C-GET reverse stores read through the cancel-safe framer; empty provider streams no longer report success; SR sequences marked D are emptied instead of recursed (PS3.15 PHI). |

## Behaviour and API changes

- `radicom_network::client::...::store_to_destination` returns `(SubOperationSummary, Option<NetworkError>)`
  so a mid-batch transport failure keeps the delivered counts.
- `Command::to_dataset()` no longer contains `(0000,0000)`; the writer inserts it at encode time.
- Saving a file inserts `FileMetaInformationVersion` when missing; `SkipLargeTags` omits the attribute
  instead of writing a placeholder; `AddFrame` appends instead of replacing the fragment sequence.
- `read_file_meta` reads only the header and group 0002 (same signature).
- New: `cargo xtask coverage [--min PCT] [--lcov PATH]`, plus a CI `coverage (95% floor)` job.
