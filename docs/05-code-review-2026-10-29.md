# Code Review — 2026-10-29

A full read-through of the workspace against **fo-dicom 6.0.0-alpha1** (source read locally) and the
DICOM standard (PS3.3/3.5/3.6/3.7/3.8/3.10/3.15/3.18), then fixes, regression tests, a coverage
floor, and benchmarks. Image codec implementations (`radicom-codecs`) are out of scope by design.

## Method

- Three independent reviewers walked disjoint areas (core model/IO/encoding/validation,
  `radicom-network`, and pixel/render/print/media/SR/anonymizer/rules/json) plus a Lead pass over the
  final diff. Every finding was confirmed by reading the real flow and, where practical, by a probe
  test before fixing.
- Finding IDs were tracked in `CORE-*`, `NET-*`, `FEAT-*` and classified P0–P3. **Every confirmed
  defect was fixed** (P0 1, P1 18, plus the P2/P3 items listed below); each fix carries a regression
  test, and the follow-up round added the missing ones (see [Follow-up](#follow-up-round-2026-10-30)).
  Where a fix is a pure work reduction with no output difference (CORE-05, CORE-11) the test pins the
  result, not the optimisation. Feature increments found during the review are deferred in
  [06-backlog.md](06-backlog.md), not left as silent gaps. The numbering has gaps — `CORE-15`,
  `CORE-16`, `FEAT-19` and `FEAT-22` were merged into their neighbours and never assigned.
- No test was weakened. Wire-format goldens were changed only where the old bytes violated PS3.8
  (the P-DATA maximum was body-only). No new dependency was added; no fo-dicom-shaped abstraction was
  introduced.
- The coverage metric is **production lines only**: test/bench/example targets and inline
  `#[cfg(test)]` modules are excluded (`cargo xtask coverage`), because a per-module test count is
  easy to inflate.

## Follow-up round (2026-10-30)

A verification pass over this report found that every named defect was fixed, but also found defects of
the same *classes* that the report did not cover, plus a few claims that were wider than the code. Both
are now resolved:

| Item | What was wrong | Fix |
|---|---|---|
| CORE-17 (residual) | The temp-file race was fixed in the `FileWindow` spill only; the C-STORE spool still used `File::create` on a clock+counter name in the shared temp directory (PHI, world-readable) | One helper, `radicom::io::temp::create_unique_file` (random name, `create_new`, `0600` on Unix), now backs the spill, the C-STORE spool and `TempFileProvider`; `write_and_parse` writes through the returned handle instead of re-opening the path |
| NET-05 (residual) | The 1 GiB cap was per `(context, stream)`, so 128 contexts × 2 streams could hold 256 × 1 GiB | `PdvAssembler` also enforces a total (`2 × max_message_length`, 2 GiB by default) and drops the partial buffer on refusal |
| JSON (residual) | The byte-backed string branch dropped zero-length components, so `A\\B` exported as VM 2 instead of 3, unlike the Str-backed branch | Empty components export as `null` (PS3.18 Annex F) and round-trip back to an empty component |
| NET-04 (comment) | `UserIdentityPolicy::Accept` was still documented as "the AC carries no response" | Comment now matches the code (empty positive response, PS3.8 §D.3.3.7) |
| FEAT-26 (guard) | The UID-literal guard scanned three files in one crate | It now walks every production source in every crate, with an explicit allowlist for the files that *define* the constants; `client.rs`'s eight inline syntax literals use the named constants |
| FEAT-13 (comment) | Claimed "every registered class is classified" | Comment states that the list is curated over generated constants, with the `Image` fallback |
| Docs / tooling | `cargo xtask …` was documented as a local alias but no alias shipped, so the documented commands failed; the README said `cargo xtask generate` (the task is `gen-dict`) | `.cargo/config.toml` ships the alias (`.gitignore` keeps the rest of `.cargo/` out), README corrected |
| Tests | NET-08 (missing Status), the C-GET empty-stream arm, CORE-09 (large preview) and CORE-10 (dataset not read) were untested or only tested with inputs that pass on the old code | Regression tests added; CORE-09 now dumps a 256 KiB window and asserts a bounded preview, CORE-10 uses a truncated deflate body so a full-file read fails |

Two review items are work reductions with no observable output difference (CORE-05's skipped length pass
and CORE-11's swapped-byte cache), so their tests pin the result rather than the optimisation; the
existing benchmark suite is what guards the cost.

## Behaviour and API changes

- `radicom_network::client::...::store_to_destination` returns `(SubOperationSummary, Option<NetworkError>)`
  so a mid-batch transport failure keeps the delivered counts.
- `Command::to_dataset()` no longer contains `(0000,0000)`; the writer inserts it at encode time.
  `CommandField::writes_priority()` gates `(0000,0700)`; AC/RJ/RELEASE/P-DATA goldens regenerated where
  the old bytes carried an illegal Priority.
- C-STORE receive paths parse with the negotiated transfer syntax and answer 0xA900 when the dataset
  SOP Class/Instance disagree with the command; `NetworkError::PeerViolation` is the only abort signal.
- The dead engine API (`EngineOptions`, `CircuitBreaker`, `PduQueue`, `ConnectionLifecycle`,
  `PendingRequest`) and the unwired watchdog state were deleted; `PendingTable` is now just the
  in-flight message-ID set.
- Saving a file inserts `FileMetaInformationVersion` when missing; `SkipLargeTags` omits the attribute
  instead of writing a placeholder; `AddFrame` appends instead of replacing the fragment sequence.
- `read_file_meta` reads only the header and group 0002 (same signature).
- `RawImage::new` asserts the BGRA length (documented) and `try_new` returns `Error`; print setters are
  plain `&mut self`, and `IconGenerator::generate_frame` has no silent default.
- `PdvAssembler` refuses a message above `max_message_length` (1 GiB) *and* more than twice that
  buffered across all in-flight messages, so a peer cannot hold one message per presentation context.
- New public helper `radicom::io::temp::create_unique_file`: the only way the workspace creates a
  temporary file (random name, `create_new`, `0600` on Unix).
- New: `cargo xtask coverage [--min PCT] [--lcov PATH]`, `cargo xtask gen-dict --check` (wired into
  CI), a CI `coverage (95% floor)` job, and `DICTIONARY_VERSION` generated from the dictionary XML.
  `.cargo/config.toml` ships the `xtask` alias those commands rely on.
